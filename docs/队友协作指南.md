## 二、开分支（每次都这样，别省）

```bash
git checkout main
git pull
git checkout -b feature/你的名字-干什么
```

⚠️ **不要直接往 main 推。** 你推的每一行都会立刻进演示版本，
也可能把别人正在改的东西盖掉（真实发生过）。

## 三、提交前跑两条

```bash
npm run format     # 统一格式（只格式化你自己的文件夹）
npm run build      # 确保能构建
```

然后开 PR，或者至少在群里说一句「我合一下 xxx」，别自己合。

## 四、两个已经踩过的坑

### 坑 1：不要把整个仓库 clone 到自己仓库里面

**症状**：根目录冒出一个 `zuoye` 文件夹；或者
`git status` 里它显示成一整条记录，提交记录里出现
`160000 commit xxx zuoye`。

这个叫「**子仓库引用**」（gitlink）。后果：别人 clone 下来会多一个**空目录**，
`git submodule` 还会报错。

**怎么清**：

```bash
git rm --cached zuoye        # 只从 git 里摘掉，不删你磁盘上的文件
echo "zuoye/" >> .gitignore  # 防止下次又被 add 进去
git commit -m "chore: 去掉误提交的子仓库引用"
```

### 坑 2：分支放太久会「落后」到没法合

`integrate/sqlite-backend` 落后 main **14 个提交**，就是这么拖出来的 ——
合的时候满屏冲突，只能一条一条手工搬。

→ **分支活不过一两天。** 做完就提 PR，别攒。
