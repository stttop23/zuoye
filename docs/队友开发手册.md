## 1. 第一次拿到代码（只做一次，约 5 分钟）

### 第 1 步：确认电脑装好了 Node.js

打开 VS Code → 菜单栏「终端」→「新建终端」，输入：

```bash
node -v
```

看到类似 `v24.19.0` 的版本号就说明装好了。没装就去 <https://nodejs.org/> 下载 **LTS 版**，一路下一步。

### 第 2 步：下载项目

在终端里依次输入（一行一行来）：

```bash
cd D:\            # 或者你想要放项目的盘，比如 cd C:\Users\你的用户名\Desktop
git clone https://github.com/stttop23/zuoye.git
cd zuoye
```

### 第 3 步：切换到**你自己的**分支

```bash
git checkout feature/luo-xinyu      # 罗欣雨用这行
```

```bash
git checkout feature/zhang-jing     # 张晶用这行
```

> ⚠️ 千万不要跳过这步在 `main` 分支上写代码，否则会和别人冲突。

### 第 4 步：安装依赖并启动

```bash
npm install      # 第一次必须执行，大约 1-3 分钟，会下载一堆文件，正常现象
npm run dev
```

终端出现下面这样就是成功了：

```
  ➜  Local:   http://localhost:5173/
```

按住 `Ctrl` 点击那个地址，浏览器就能看到页面。

### 第 5 步：找到你的页面

在浏览器地址栏手动加上路径：

- 罗欣雨：<http://localhost:5173/leave>
- 张晶：<http://localhost:5173/todo>

**能打开看到内容 = 你已经成功了。** 剩下的都是改代码。

> 💡 没有 VS Code 的话去 <https://code.visualstudio.com/> 下载。打开项目：VS Code 菜单「文件」→「打开文件夹」→ 选 `zuoye` 文件夹。右侧弹出的推荐插件（Volar、Prettier）请点安装。

## 2. 每天开工前 / 收工后，固定两个动作

**开工前**（把刘皖和其他人的最新代码同步下来）：

```bash
git checkout main
git pull
git checkout feature/luo-xinyu      # 换成你自己的分支
git merge main
```

**收工后**（把今天的成果传上去）：

```bash
git add .
git commit -m "feat: 完成请假申请表单"
git push
```

就这两件事，养成习惯能躲掉 90% 的麻烦。

## 4. 写代码时的规矩（很重要，不然合并时会打架）

### ✅ 可以随便改

- `src/views/LeaveView.vue` 或 `src/views/TodoView.vue` —— **你自己那一个文件**

### 🚫 不要动（要改先在群里说一声）

| 文件 | 为什么 |
| --- | --- |
| `src/main.js` | 入口文件，三个人同时改必冲突 |
| `src/router/index.js` | 路由表由刘皖统一维护 |
| `vite.config.js`、`package.json` | 会影响所有人的环境和依赖 |
| `src/assets/styles/variables.css` | 全局配色，要加颜色先跟刘皖说 |
| `src/views/其他文件名.vue` | 那是别人的地盘 |

### 样式必须用变量，不许写死颜色

```css
/* ✅ 正确 */
color: var(--st-text-primary);

/* ❌ 错误 */
color: #303133;
```

打开 `src/assets/styles/variables.css` 可以看到所有可用变量，命名都以 `--st-` 开头。

### 页面专属样式写在 `<style scoped>` 里

`<style scoped>` 表示"这些样式只对本文件生效"，不会污染别人的页面。

### 多利用 Element Plus 现成组件

表格用 `el-table`、弹窗用 `el-dialog`、表单用 `el-form`，不要自己手写。
官方文档：<https://element-plus.org/zh-CN/component/table.html>

## 5. 提交代码 + 开 PR 的完整流程

### 第 1 步：先自测（别偷懒）

- [ ] 页面能正常打开，不白屏
- [ ] 所有按钮点一遍都有反应
- [ ] 按 `F12` 打开控制台，**Console 里没有红色报错**
- [ ] 按 `F5` 刷新页面，没有报错

### 第 2 步：提交并推送

```bash
git add .
git commit -m "feat: 完成请假申请页面"
git push
```

提交信息前缀规范：

| 前缀 | 什么时候用 |
| --- | --- |
| `feat:` | 新增功能 |
| `fix:` | 修好了一个问题 |
| `style:` | 只改了样式 |
| `docs:` | 只改了文档 |

### 第 3 步：在 GitHub 上开 PR

1. 打开 <https://github.com/stttop23/zuoye>
2. 页面顶部会有一条黄色提示「**feature/luo-xinyu had recent pushes**」，点右边的 **Compare & pull request**
   （如果没看到提示，就点 **Pull requests** → **New pull request**，左边选 `main`，右边选你的分支）
3. 标题写清楚，比如「完成请假申请页面」
4. 点绿色的 **Create pull request**
5. **然后去群里 @刘皖 说一声**，等他合并

> PR 就是"我改好了，请帮我把我的分支合并进 main"。合并之后你的代码才真正进主分支。

## 6. 如果报错了 / 冲突了

### 常见报错速查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `npm error ... package.json` 找不到 | 终端不在项目目录 | `cd` 到有 `package.json` 的那一层（`zuoye` 文件夹） |
| `'npm' 不是内部或外部命令` | Node 没装好 | 重装 Node，安装时勾上 **Add to PATH** |
| 页面白屏 / 控制台红字含 `Failed to resolve import` | import 路径写错了 | `@` 代表 `src`，检查文件名大小写 |
| `Port 5173 is in use` | 上次的服务器还在跑 | 终端按 `Ctrl + C` 停掉，再 `npm run dev` |
| 改了代码页面没变化 | 改错文件了 | 看浏览器地址栏的路径，对应用哪个 `.vue` |
| `git push` 被拒绝（rejected / non-fast-forward） | 远程有新提交你没有 | `git pull` 之后再 `git push` |
| VS Code 满屏是红色的「删除行 / 添加行」 | 换行符问题 | 已用 `.gitattributes` 解决，**不要修改这个文件** |

### 出现冲突（Conflict）怎么办

冲突只会发生在**两个人改了同一个文件**时。正常遵守第 4 节的规矩就不会遇到。

万一遇到了，**不要自己乱点**，直接截图发群里。最简单的处理方式：

```bash
git checkout feature/你的分支
git fetch origin
git merge origin/main
# 此时会列出冲突的文件
```

打开冲突文件，会看到这样的标记：

```
<<<<<<< HEAD
你的代码
=======
别人的代码
>>>>>>> origin/main
```

把这三行标记删掉，手动保留正确的那份代码，保存，然后：

```bash
git add .
git commit -m "fix: 解决合并冲突"
git push
```
