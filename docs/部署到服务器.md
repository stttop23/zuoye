# 部署到服务器（47.114.62.248）

> 这份文档是照着「**本地打包 → 上传静态文件 → nginx 托管**」写的，
> 因为这是最省事、最不容易出错的路子。服务器上不需要装 Node。

## 零、先说清楚上线之后会变成什么样 ⚠️

这一条最重要，**别部署完发现 AI 变笨了就以为坏了**：

| 功能 | 本地开发时 | 部署到服务器后 |
| --- | --- | --- |
| AI 填表 / 查数据 | 本机 Ollama 的 qwen2.5:7b，聪明 | **降级成后端正则规则**，能填表但听不懂复杂说法 |
| 打卡的经纬度 | 需要 https | **需要 https**，http 下浏览器直接拒绝给位置 |
| 打卡的**地名** | 走 Flask 代理 → 高德 | 挂了 Flask 代理才有效，否则只显示坐标 |
| 其他所有页面 | — | 一模一样 |

**为什么 AI 会降级**：模型跑在**你自己的笔记本**上（`E:\ollama`，4.4GB）。
服务器上没装 Ollama，Flask 代理去连 `127.0.0.1:11434` 连不上，
就按设计退回「本地正则规则」那条路 —— 这句是系统本来就有的降级机制，不是 bug。

> 所以：**答辩演示建议还是用本机的 `npm run dev`**（AI 才是完整的）。
> 服务器主要是给同学/老师**点开看看界面**用。

---

## 一、本地打包

```powershell
cd d:\zuoye
npm run build          # 产出 dist/
```

`dist/` 里就是全部静态文件（≈1.1 MB）。**不需要改任何环境变量** ——
前端请求走的是相对路径 `/api`，由 nginx 转发，写死不了。

> ⚠️ 打完包记得 `Remove-Item -Recurse -Force dist` 别把它提交进 git
> （`.gitignore` 里已经忽略了，但手动删一下更保险）。

## 二、清掉服务器上的旧内容

⚠️ **先看，再删。** 别上来就 `rm -rf`。

```bash
# 1) 看 nginx 到底在服务哪个目录、有哪些站点
nginx -T | grep -E 'root |server_name|listen'

# 2) 看目录里有什么
ls -la /var/www/
ls -la /usr/share/nginx/html/
```

现在 `47.114.62.248` 上放的是瀚荒寰宇的「已迁站」提示页
（指向 `https://hanhuanghuanyu.cn/`，页面自己写着「本页以外的地址已经全部关闭」）。

**删之前想一下**：还用旧 IP 访问的人，删了提示页就找不到新地址了。
建议保留它、挪到子路径，把根路径让给新项目：

```bash
# 建新目录
sudo mkdir -p /var/www/zuoye

# 想保留提示页的话，把它挪过去（文件名按实际改）
sudo mkdir -p /var/www/hanhuang-notice
sudo mv /var/www/<旧目录>/index.html /var/www/hanhuang-notice/
```

> ⚠️ 两个保命提醒：
> 1. **`rm -rf` 后面绝对不要多打空格**：`rm -rf /var/www/foo /` 是删根目录。
> 2. 删之前 `nginx -T` 确认路径 —— 有时候 nginx 服务的目录跟你想的不是同一个。

## 三、上传 dist

**方式 A：scp（Windows 10+ 自带）**

```powershell
cd d:\zuoye
scp -r dist\* root@47.114.62.248:/var/www/zuoye/
```

**方式 B：宝塔面板** —— 直接把 `dist` 里的文件拖进 `/var/www/zuoye`。

**方式 C：先打包再传**（文件多的时候快一些）

```powershell
cd d:\zuoye
Compress-Archive -Path dist\* -DestinationPath zuoye-dist.zip -Force
scp zuoye-dist.zip root@47.114.62.248:/tmp/
# 服务器上：cd /var/www/zuoye && unzip -o /tmp/zuoye-dist.zip && rm /tmp/zuoye-dist.zip
```

传完检查一下权限（nginx 要能读）：

```bash
sudo chown -R www-data:www-data /var/www/zuoye    # 有些系统是 nginx:nginx
sudo chmod -R 755 /var/www/zuoye
```

## 四、配置 nginx

把仓库里的 `deploy/nginx-zuoye.conf` 传上去，然后：

```bash
sudo cp deploy/nginx-zuoye.conf /etc/nginx/conf.d/zuoye.conf
sudo nginx -t                 # ⚠️ 先测！没过就别 reload
sudo systemctl reload nginx
```

**⚠️ 最容易踩的一行**：配置里那句

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

少了它，打开首页正常，但**一刷新 `/todo`、`/leave` 就是 404** ——
因为服务器上根本没有 `todo` 这个文件，那几个页面是前端路由自己画的。
nginx 找不到文件就直接报 404，得有这句把它兜回 `index.html`。

## 五、（可选）挂 Flask 代理

只有想让**打卡显示地名**、或者以后接了后端接口才需要。
不带它：AI 走前端本地兜底，打卡只显示坐标，其他页面照常。

```bash
# 服务器上
pip3 install flask requests python-dotenv gunicorn     # 或 pip3 install -r requirements.txt gunicorn
cd /var/www/zuoye-server                                # 把 server/ 目录整个传上来
gunicorn -w 2 -b 127.0.0.1:5000 app:app                 # 想常驻就用 systemd
```

`server/.env` 里至少要：

```
OLLAMA_ENABLED=0        # 服务器上没模型，直接关掉，别让它白等超时
AMAP_KEY=你的高德key     # 不填也行，只是打卡不显示地名
```

> `OLLAMA_ENABLED=0` 这一条建议加上：不然每次聊天都要等 ollama 连接超时，
> 用户会觉得「点了没反应」。

## 六、排错

| 现象 | 多半是 |
| --- | --- |
| 首页空白，控制台 404 | `root` 指错目录了，`nginx -T` 看一眼 |
| 刷新子页面 404 | 少了 `try_files ... /index.html` |
| 页面出来了但样式全无 | `/assets/` 没读到（路径或权限问题） |
| 点 AI 一直转圈 | Flask 没起，或 `.env` 里 `OLLAMA_ENABLED` 没关 |
| 打卡拿不到位置 | 不是 https（浏览器硬性要求） |
| 打卡有坐标没地名 | `/api` 没转发，或没配 `AMAP_KEY` |
| 改了配置没生效 | 忘了 `reload nginx`，或者改错文件了（`nginx -T` 看实际加载的） |
