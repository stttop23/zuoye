---

## 一、一句话架构

```
浏览器输入 /leave
   ↓  Vue Router 按路由表匹配
   ↓  BasicLayout 渲染外壳（侧边栏 + 顶栏 + 面包屑）
   ↓  <router-view> 塞进 views/leave/index.vue
   ↓  页面从统一 appStore 读取业务数据
   ↓  appStore 通过 Flask API 与 SQLite 同步
```

**两个决定性的设计：**

1. **`BasicLayout` 只写一次。** 侧边栏、顶栏、面包屑、菜单高亮全部在这里，队友的页面只管「内容区」，不需要碰导航。所以队友改页面永远不会改坏别人的导航栏。
2. **路由表集中在一个文件。** `src/router/index.js` 由你独占维护，队友不碰。这是全组唯一会「被三个人同时改」的文件，把它锁死，冲突就少了最大的一块。

**核心规则：一个人 = 一个根目录文件夹 = 一行路由。**
成员目录里的 `index.vue` 只做「组装」，表格 / 表单 / 弹窗放到同级的 `components/` 里。
文件夹是私有的，路由行是共有的但由你代填。

> `src/` 里放的是三个页面共用的外壳（入口、路由、布局、全局样式、共享状态），
> 不属于任何一个人。

## 三、分层结构

```mermaid
graph TD
    A["src/main.js<br/>注册 Element Plus / 路由 / 全局样式"] --> B["src/App.vue<br/>只放 router-view"]
    B --> C["src/layout/BasicLayout.vue<br/>侧边栏 + 顶栏 + 面包屑"]
    C --> D1["liuwan/views/dashboard/index.vue"]
    C --> D2["liuwan/views/notice/index.vue"]
    C --> D3["luoxinyu/views/leave/index.vue"]
    C --> D4["zhangjing/views/todo/index.vue"]
    C --> D5["liuwan/views/contacts/index.vue"]
    D1 --> E1["dashboard/components/<br/>StatCards · QuickActions · RecentNotices"]
    D2 --> E2["notice/components/<br/>NoticeFilter · NoticeTable · NoticeDetailDialog"]
    D3 --> E3["leave/components/<br/>LeaveForm · LeaveRecords"]
    D4 --> E4["todo/components/<br/>TodoStats · TodoToolbar · TodoDialog"]
    E1 -.-> F["src/assets/styles/variables.css<br/>--st-* 全局变量"]
    E4 -.-> F
```

**每个页面都是「两字结构」：**

| 文件 | 职责 |
| --- | --- |
| `index.vue` | 只做组装：拿数据、管状态、把子组件拼起来 |
| `components/*.vue` | 具体的一块界面（表格 / 表单 / 弹窗），通过 props + emit 和父级通信 |

**样式是自上而下单向覆盖的：**

```
element-plus/dist/index.css   ← 组件库默认样式
        ↓ 被覆盖
variables.css                 ← 你的 --st-* 变量
        ↓ 被覆盖
页面自己的 <style scoped>      ← 只影响自己那个页面
```

所以 `main.js` 里这两个 import 的顺序不能调换：

```js
import 'element-plus/dist/index.css' // 必须在前
import '@/assets/styles/variables.css' // 必须在后
```

## 四、数据流

| 阶段 | 数据从哪来 | 要改哪里 |
| --- | --- | --- |
| 页面状态 | `src/composables/appStore.js` | 所有页面、通知、AI 共用 |
| 持久化 | Flask `/api/workspace` | `src/api/workspace.js` |
| 数据库 | `server/student_work.db`（SQLite） | 首次启动自动建表、写入种子数据，并迁移已有浏览器缓存 |
| 通讯录 | `src/mock/index.js` | `DIRECTORY_CONTACTS` 为通讯录演示数据，页面支持姓名/部门搜索与部门筛选 |

启动前端前先运行 `python server\app.py`；Vite 将 `/api` 代理到本机 Flask 服务。首次启动优先将已有浏览器缓存迁入数据库，之后以 SQLite 为权威数据源；变更会自动写回 SQLite，`localStorage` 只作数据库不可用时的本地缓存。
当前演示版没有用户登录认证；局域网内能访问前端的设备也能读写数据库，请勿暴露到公网或不可信网络。

## 五、三条铁律（防止冲突）

1. **不碰别人的文件夹。** 需要改别人的页面，先在群里说，让对方改。
2. **不碰 `router/index.js`。** 你的路由行已经配好了，不需要动。真要加页面，找刘皖加。
3. **颜色只用变量。** 想用一个变量表里没有的颜色，找刘皖加到 `variables.css`，不要自己写 `#xxxxxx`。

## 六、你（刘皖）要守住的事

- ✅ `main` 分支永远能跑起来。每次合并 PR 前先 `npm run build`，报错就打回去。

- ✅ 队友说「我要加一个新页面」时，由你改 `router/index.js` + 给菜单加一行，不要让她自己加。
